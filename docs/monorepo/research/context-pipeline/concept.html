Pipeline design · nothing here is built

A fixed pipeline a board can extend

Forge's phases stay forge's. A board switches on a plan, and fills the hook points between the phases with hooks: a command, an agent or a person, each doing whatever that board needs at that point.

Phases are fixed

Intake, plan, build, review, merge, in that order. Each delivers an artifact. Only build and review change code.

Hooks are the board's

At six hook points, an ordered list. Forge knows three things about a hook: what it reads, whether it can stop the flow, what it produces.

A board that adds nothing

behaves as forge does today. Gates, ticket review and merge approval are untouched.

Six words carry the design.[18]

The anatomy of a hook

Runs by

A command, an agent with a brief and a model, or a person with a role.

Reads
ticketplanan earlier hook's artifacta snapshot of the code
Blocks

Whether its "no" stops the flow. If it does, the hook says what the no does: return the work to the phase before it, or halt for a person.

Produces

Named artifacts, each with the headings it must have. A later phase or hook names them to get them.

A hook never

works in the ticket's worktree. One that reads code gets a snapshot of the commit handed over, to use and throw away.

A hook never

is a phase's conversation. A person's hook is a halt that ends on accept.

Everything else about a hook is its own business: a check, an analysis, a report to another system, a statistics run.

What forge does with a hook

Forge waits for every hook, in the order the board lists them. A hook ends in a yes, a no, or it could not run. The declarations decide what each does.

BlocksProducesA "no"Could not runExample
NoNothingHas no meaningRecorded and shown; the flow continuesA notifier, a statistics tracker
NoArtifactsHas no meaningThe ticket waits for a personTest criteria that the reviewer reads
YesNothingReturns the work, or halts for a personThe ticket waits for a personA check on the plan
YesArtifactsThe same, with the artifacts as findingsThe ticket waits for a personAn architecture verification with its report
A personNothingNone: it halts until acceptDoes not applyAn approval

A command says no through its exit status, as a gate does. An agent says no through a verdict in its report, as a reviewer does.[11] A person never says no: the hook halts until accept, and what the person does before that (reads, edits the artifact, sends findings to the builder, nothing) is outside the flow and on record.

04The rules

The whole design as rules, grouped by what they govern.[18]

Left out on purpose

  • A phase that a board defines, and any other order of phases.
  • A hook that is a conversation, and a hook that changes code. So a hook cannot commit a design record or a changelog, and a separate agent cannot write tests before the build.
  • A hook on the merged tree. Only the merge gates see it.
  • A hook that runs once for a release instead of once for a ticket.
  • Two hooks of one hook point at the same time.
  • A short lane that lets a small ticket skip a phase or a hook.
  • A trigger outside forge. A hook after the merge can already report to another system.
  • Identity, permissions and roles that are enforced.

What it makes possible

  • Thinking before building. A plan, checked and approved if the board wants that, before a builder spends a token. Today the only document before the build is the ticket.[2]
  • Checks forge never designed: an architecture verification, a test evaluation, a security read, each a hook with its own brief.
  • Deliverables of a board's own. A hook produces an artifact, a person approves it, a later phase reads it.
  • Soft gates. A check that continues when green and asks a person when red.
  • Forge reporting outward: a notifier at any hook point, a release note after the merge.
  • Replay and pricing. Every phase and hook has declared inputs at known versions, which is the record the compounding research asks for.[14]

The version that fails: hooks as a plugin system

A hook may do anything, anywhere, at any time: write code, hold a conversation, run beside the flow, stand in for a gate. It demos well in a week.
