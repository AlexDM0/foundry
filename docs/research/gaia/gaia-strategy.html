Gaia: one window over every forge on this machine

Each forge already runs itself: one Overseer per board, its own Bridge, its own agents. Gaia sits on top of the forges that happen to be running and answers the one thing none of them can: across all of them, where am I needed right now?

The pitch

What Gaia does

Tells you where you are neededEvery question, review, merge accept and draft that waits on you, from every forge, in one list. Oldest first, escalations on top. It also flags a forge that needs a look: an Overseer that stopped with work ready, held launches, a usage limit.
Shows every agent on the machineOne table of all builders, reviewers, intakes and Assistants, grouped by forge, with state, calls against budget, last tool and tokens. The same facts the Bridge's Agents view shows, for all forges at once.
Is one window, not a frame around othersPick a forge in the rail and its Kanban, Questions or Intake open in the same window, in the same design language, with no second header and no second tab bar.
Lives in the Dock and the menu barA macOS app with a badge that counts what waits on you, and a notification when a forge asks. You stop checking tabs.
Adds nothing to trustGaia runs no agents and writes no tracker file. It reads what forges publish and sends your clicks to the forge that owns them. Quit Gaia and every forge keeps working.
Today, with four forges
  • Four browser tabs, one forge open per repository to get each.
  • Each Bridge has its own Waiting on User pill. You learn that a forge needs you by visiting it.
  • An Overseer restart drops the Bridge's session, so the tab reads nothing until you run forge open again.
  • A stopped Overseer is silent. Ready tickets wait and nothing says so.
  • No view answers "how many agents are running on this machine and what are they costing me today".
With Gaia
  • One window. Forges are found on their own, running or not.
  • One attention list across forges, mirrored in the Dock badge, the menu bar and notifications.
  • Gaia holds each forge's access itself, so a restarted Overseer reconnects without a terminal.
  • A stopped forge with ready work shows up as something to act on, with a Start button.
  • Machine totals: agents working, done today, tokens today, queue, the shared usage limit.

How it works

A reader and a relay, with no state of its own

Gaia is one Bun server on 127.0.0.1 and one React page. The server finds the forges, reads each one, folds them into one model of the machine and streams that to the page. Your clicks go back the same way: the page tells the Gaia server, and the server sends the command to the forge that owns it. A macOS shell puts the page in a window.

The page never talks to a forge's API itself. It cannot: every Overseer refuses requests from another origin and answers no CORS preflight. That guard is the reason Gaia has a server at all, and it is a good reason, so the design keeps it.

Finding forges

Every forge already writes itself into ~/.forge-monitor/projects.json, and a starting Overseer adds its URL and process id to its entry, then removes them when it stops. Gaia watches that one file. For each entry with a URL it asks GET /api/identity and checks that the tracker id matches, so a stale pointer from a crashed Overseer reads as stopped and a foreign program on the port reads as not a forge. No scanning, no network discovery, no forge has to know Gaia exists.

Reading

A running forge is read over its API. A stopped forge is read by running forge status --json in its root, which takes no lock. Both are mapped at the boundary into one fleet model. Gaia never recomputes a count or a rule a forge already owns: what waits on you, how many slots are free and what a job may do arrive as facts.

Acting

Answer, Ready, Accept, Pause and the rest are the forge's own control commands, posted to that forge's POST /api/commands with that forge's token. A refusal comes back as the forge worded it and is shown verbatim. Starting an Overseer is forge oversee --detach, run in the repository. Gaia has no other way to change anything.

Being optional

Nothing in a forge waits on Gaia. A forge that predates a Gaia feature is shown with what it can provide and marked as such. Gaia keeps only its own preferences and its server record, under ~/.forge-monitor/gaia/. Deleting that folder loses nothing a forge needs.

Gaia's own server takes the forge's guards as its model: bound to 127.0.0.1, Host and Origin checked, a session for its page, a content security policy on every answer. It holds tokens for several forges, so it reads each token from its file per request and keeps none on disk.

For the sparring session

Decisions that are yours

  1. Is the hybrid the "integrated whole" you have in mind? My reading: one window and one navigation, with each forge still rendering its own board. If you meant Gaia renders everything itself, the forge needs a versioned board contract first and Gaia becomes several times larger.
  2. May Gaia act, or only show? I have assumed it relays your clicks, including Answer, Ready, Accept and Pause. A first version could be read-only and send you to the forge for every action.
  3. May Gaia start an Overseer? "Talks with the forges and needs no agents of its own" still allows it to run forge oversee --detach on your click. It never starts one unasked. Say if even that is too much.
  4. Which shell? I recommend a short Electrobun spike with the Swift wrapper as fallback. If you would rather have no dependency at all, the Swift wrapper comes first.
  5. Only forge boards? I have assumed Gaia reads ~/.forge-monitor only, and that v1 agent-progress boards stay with agent-dashboard until they move over.
  6. A machine-wide agent limit? Each forge has its own "agents at most". Gaia could show the sum, or you may want one budget shared across forges. The second is new forge policy, not a Gaia feature, so I left it out.
  7. Where does the shared design system live? A package in your registry beside @reliquary/eslint-config, or a folder both repositories reach.

Left out on purpose

  • Agents, sessions or a chat of Gaia's own. Intake and the Assistant stay in each forge.
  • Writing a tracker file or the registry. Only forges write them.
  • Access from another machine or a phone. Everything stays on 127.0.0.1.
  • Replacing the Bridge. A forge without Gaia loses nothing.
