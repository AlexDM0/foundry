ONE FORMAT. Every figure is a hand-authored SVG rendered to PNG with the owner's `diagrams` skill. Read `~/.claude/skills/diagrams/SKILL.md` and `references/design-system.md` first and start from `assets/template.svg`. No Mermaid, no generated charts, no screenshots inside figures.

FILES. Source and PNG sit together: `docs/figures/<doc-slug>/<figure-name>.svg` and `.png`, where doc-slug is the document's plan slug. The owning writer owns that folder. Names are kebab-case and say the content. Render one figure with `python3 ~/.claude/skills/diagrams/scripts/render.py docs/figures/<doc-slug>/<figure-name>.svg`. Exception: the README's four diagrams stay in docs/images/ and render with `.readme-graphics/render-diagrams.py`. Bridge screenshots in docs/images/ are photographs of the product, not figures.

EMBEDDING. Documents embed the PNG, never the SVG, by relative path: `![Alt text.](../figures/<doc-slug>/<figure-name>.png)`, then one italic caption line stating what to notice. Figures are unnumbered, so a reviewer can add one without renumbering; refer to a figure by its idea. Alt text is real: one to three sentences giving the content and the conclusion, including the main path and its exits. An alt that says 'diagram of X' fails. A figure belongs to one document; others link that document, never embed a copy.

ONE IDEA. Each figure teaches one idea, statable in one sentence before drawing. If the sentence needs 'and', split it. The card title states that conclusion ('The Overseer reads files and writes sockets'), not a topic. Normal figures hold at most about 12 boxes; matrices and swimlanes may hold more if they stay legible. Boxes hold a short title and at most a five-word subtitle. Explanation belongs in the prose. A plain lookup table stays Markdown; a table figure is welcome only when a grid teaches by shape. A figure that only restates a table or a key list in its own document is cut.

COLOUR MEANS WHO, across the whole set, so a reader learns it once:
Blue: code that decides or acts (Overseer, Pass, Playbook, Customs, Airlock, Bouncer, Watcher).
Coral: agent sessions, reports, and anything untrusted.
Gray: stored state and inert things (files, git, logs).
Amber: a person, or anything waiting on or held for one (User, decisions, holds, processless states).
Green: a good outcome (passed, landed, merged, survives).
Red: failure or refusal.
At most three ramps plus gray per figure; four on topology or matrix figures. Text takes the 800 stop of its own ramp, subtitles 600 or 700, exact hex from design-system.md. Never black on colour. A state machine colours states by who acts, not by status.

GEOMETRY. viewBox width 680, safe area x 40 to 640. Matrices and wide swimlanes may go to 1000 wide. Height fits content. Text no smaller than 11 at width 680, and no smaller than 13 at width 1000. Weights 400 and 500 only. System sans; `ui-monospace` for identifiers and paths. Title 18, subtitle 13, box title 14, box subtitle 12, edge label 11. One arrow marker, lines `#bfbdb0` at 1.6. Dashed means reads only or optional. A shaded band means a lock is held or a span where nobody drives. Labels sit beside lines, never on them. Arrows never cross an unrelated box. The card is full-bleed warm `#FAF9F5`, `rx=16`, hairline `#ECE7DC`.

SAME SHAPE FOR THE SAME CONCEPT. Swimlane for sequences across actors, lanes left to right from person to code to store, time down. Ladder for escalation. Strip for one Pass over time. Git graph with the same lane order. State diagram: normal path straight, exceptions peeling off, edges labelled with the trigger.

ACCESSIBILITY. The root `<svg>` has `role="img"` with `<title>` and `<desc>` as its first children; `<desc>` carries the alt text's content. Retired names must not appear in any SVG, `<desc>` included.

VERIFY. Read every PNG back with the Read tool. Check clipped text, labels on lines, arrows through boxes, overflow past the safe area. Values on a figure are code facts, verified like prose; prefer a constant's name where a value may change. No figure may claim what its document does not support.

INTERACTIVE PAGES. `docs/interactive/<slug>.html`, one self-contained file: inline CSS and JS, no CDN, no fetch, no web fonts, no build step, working over file://, under 200 KB. Same who-colours through CSS custom properties on `:root`, redefined for dark under `@media (prefers-color-scheme: dark)`, with a visible light, dark and auto control that sets `data-theme`, stored in `localStorage` inside try/catch; the page works without it. Dark surface `#262624`, raised `#30302E`, text `#E8E6DC`, muted `#A3A196`. Body has an explicit background. Inline SVG, not images. Same shell on every page: a header with a link to `../README.md` and the home document, the reader's question and one sentence on what to do, controls beside result, stacking below 800 px. Works down to 375 px with no sideways scroll; full keyboard use; visible focus; `aria-live` on the area that changes; respects `prefers-reduced-motion`; state in the URL hash so a view can be linked; a `<noscript>` message with the home link. All facts live in one `MODEL` constant at the top of the script, each table naming its source path, and the page states commit 70ce56de. Logic reads the model; no fact is hard-coded in markup. Every outcome names the function that decides it. Same retired-name rule as any tracked file. Verify with the `verify-html-page` skill in light and dark: no console error, no failed request, every control exercised by a probe. The reviewer checks each MODEL table against the TypeScript constant in a scratch script.
